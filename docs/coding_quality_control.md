# 編碼品質控制

本檔記錄正式編碼的檢核流程與結果。這些檢核是研究內部的品質控管，不是正式的編碼者間信度檢定。

## 流程

1. **前測**：codebook 先以 5 件案件做前測，調整變項定義（例如把法院對財物的定性與編碼者對財物來源的中性描述分成兩欄）。
2. **樣本確認**：正式樣本為 39 件案件、42 個 actor-case。
3. **全數編碼**：42 列全部依 codebook v2.2 完成編碼。每列的事實來源判決閱讀程度標示在 `full_text_verification_status`：34 列為 complete，8 列為 relevant_sections_complete（附表很長，只讀表頭、代表性列與合計，逐筆欄位標為未記載）。
4. **證據引文抽查**：隨機抽 104 筆證據引文，對照判決全文。103 筆逐字吻合，1 筆有輕微出入，0 筆找不到。另查引文是否足以支持所編的值：80 筆支持，23 筆只部分支持，1 筆不支持。
5. **H 組全量覆核**：抽查發現部分支持不足的情形集中在 H 組控制機制和發現方式，所以對所有非「未記載」的 H 組欄位（72 格）全數重新對照判決覆核。54 格被降級：36 格降為「未記載」，18 格由「明確記載」降為「可直接確認」，沒有升級。
6. **發現方式全量覆核**：42 列的發現方式全部重新覆核，5 列有修改。
7. **修正紀錄**：編碼後的修正共 67 筆，逐筆保留舊值、新值和理由，供研究者內部稽核。
8. **第二編碼者比對**：另請一位獨立編碼者盲編其中 3 個 actor（涵蓋不同類型）。可比較的類別判斷 45 格中，40 格一致；5 格不一致，全部在 H 組。比對值見 `data/intercoder_check_public.csv`。

## 如何看待第 8 項

只有 3 個 actor、45 個類別格，不構成正式的信度估計，也不能推論整體編碼的可靠度。表中編碼者 A 的值是覆核與修正之後的最終值，因此一致率高於修正前的狀態。這項比對的用途是找出容易分歧的欄位，結果指向 H 組與發現方式。

## 未納入公開資料集的材料
